## 核心约束（必须遵守）

> 每条写成「**偏差事实 + 怎么验证**」：写"和标准框架不一样的地方""必须的规矩"，并注明验证方式（哪条命令 / 哪处代码）。
> **不写无法验证的"踩坑传说"**——坑必须落到代码里的具体位置，否则下次 AI 读了也不知道该改哪一行。

1. **<框架偏差>**：<和标准框架不一样的地方>　**验证**：<哪条命令 / 哪处代码>
2. **<返回/参数约定>**：<约定内容>　**验证**：<哪条命令 / 哪处代码>
3. **<日志/事务约定>**：<约定内容>　**验证**：<哪条命令 / 哪处代码>
4. **直写，少包一层**：逻辑放在现有函数里，能从入口顺着看到结果。不为一次调用新造接口、基类、工厂或通用层。后端沿现有控制器和服务往下写，不先搭用不上的分层。　**验证**：看本次 diff，没有只被一处调用的新抽象
5. **编码 UTF-8**：源码与文本配置一律 **UTF-8**（不要 GBK/GB2312/UTF-16）　**验证**：读文件字节，非 GBK 双字节
6. **无 BOM**：UTF-8 **不带 BOM**（禁止 `EF BB BF` / `U+FEFF`）　**验证**：读首字节，非 `EF BB BF`
7. **注释无表情**：注释与文档字符串禁止 emoji/表情符号；用文字代替（如 OK/FAIL/TODO）　**验证**：`rg` 扫 emoji 码位
8. **语言**：对话/注释/文档用简体中文；变量/类名用英文　**验证**：<代码评审>

## 工具入口（AI 直接用，别说"无法访问"）

| 用途 | Windows | Unix |
|------|---------|------|
| 写入/更新 .env（连接命令） | `./scripts/apply-mysql-dsn.ps1 -Command '...'` | `./scripts/apply-mysql-dsn.sh --command '...'` |
| 项目结构扫描 | `./scripts/scan-project.ps1` | `./scripts/scan-project.sh` |
| MySQL 交互 / 批准后的写库 | `./scripts/mysql.ps1` | `./scripts/mysql.sh` |
| 查真实状态（只读单语句） | `./scripts/db.ps1 "<只读SQL>"` | `./scripts/db.sh "<只读SQL>"` |
| 语法/类型自检 | `./scripts/lint.ps1 <文件或目录>` | `./scripts/lint.sh <文件或目录>` |
| 接口冒烟 | `./scripts/smoke.ps1` | `./scripts/smoke.sh` |
| 接口错位对账 | `./scripts/api-check.ps1` | `./scripts/api-check.sh` |
| **验收闸（完成的定义）** | `./scripts/verify.ps1` | `./scripts/verify.sh` |

日常开发（省 token）：先读 `docs/项目进度与完成度.md` 第二节和第六节最近 10 行，再只打开这些落点。需求已写清改什么、改哪里就直接改。几件独立的事，一件本轮 `Done: yes` 后再做下一件。只有对外行为变了（接口、表、路由、权限、仓库怎么摆）才同一轮改架构文档对应小节。纯重构不改架构文档。修 bug 先复现一次。收尾跑 `verify`，回复里引用本轮的 `Done: yes`。`WARN` 时在第六节补一行再重跑。有 `FAIL` 时只改第一条。任务没要求却改过的文件要在回复里点名。不要把 `docs/_scan-raw.md` 整份贴进对话。对账全量加 `api-check -All`。
